# 公告汉化

把游戏内「公告」的标题与正文替换为中文。

游戏公告的文本**不经过**官方语言包系统，因此改汉化包对公告无效。本功能利用公告缓存的一条特性：游戏判定公告是否需要下载时**只看文件是否存在**——把译好的公告 JSON 按官方同名文件名放进公告缓存目录，游戏就再也不会下载或覆盖它。

---

### 前置条件

1. **已安装带中文字体的汉化包**（如零协 `LLC_zh-CN`）。公告的中文字形来自语言包的 TMP 全局字体回退，语言包缺失时中文会显示为方块。
2. **游戏使用新版公告系统**。先启动一次游戏并进入大厅，让游戏创建公告缓存目录；若本页显示「未检测到公告缓存目录」，说明游戏尚未创建，或该账号仍在使用旧版公告（旧版公告随服务器数据下发，本功能无法覆盖）。

### 翻译服务（已内置，无需配置）

本工具只把**公告文件名**发给翻译服务（无需鉴权），服务端负责查缓存 / 拉取官方原文 / 翻译，返回整篇译好的公告 JSON。**服务地址固定为 `https://notice.lcta.top`，页面不需要填任何配置**：目标语言、请求超时、落盘校验全部由工具自动确定。

打开本页时会自动查询服务状态（服务地址与「已缓存 N 篇」都来自服务端），不需要手填地址，也不需要点「测试」才知道通不通。

**响应约定**（自建服务时需遵守）：HTTP 200，正文为 JSON 信封，由 `status` 决定语义。

```json
{"status": "ok",      "data": { …整篇公告 JSON… }}
{"status": "pending", "message": "未命中缓存，正在翻译"}
{"status": "error",   "message": "翻译引擎失败"}
```

- `data` 与官方 `NoticeDetail` 同结构，只把 `title` 与 `content.list[*].formatValue` 换成中文；`id` / `noticeType` / `startDate` / `endDate` / `sprList` / 每个条目的 `formatKey` 必须原样保留。
- **未命中缓存就回 `pending`，不要挂住请求**：本工具会自动等待重试（指数退避 1→2→4→8→16 秒后固定 16 秒，单篇最多等 60 秒），服务端不需要做长轮询或阻塞等待翻译完成。
- 服务端内部失败可回 `status: "error"`，或直接返回非 200 状态码。

公共翻译服务会**每 30 分钟自动拉一次官方公告清单并提前翻译**，所以正常情况下点「开始同步并汉化」第一次请求就能命中译文。想自建服务：仓库里带了一份参考实现 `tools/notice_server/`（独立进程，HTTP 层 FastAPI + Uvicorn），用法见 `tools/notice_server/README.md`；把 `webutils/notice/service.py` 的 `DEFAULT_SERVICE_URL` 改成自己的地址即可，协议完全一致。

### 同步与落盘

1. 点击「开始同步并汉化」。工具先取官方公告清单（`noticeMeta.json`），再按当前语言挑出目标文件名。
2. 逐篇把文件名发给服务，收到译文后先校验：`formatKey` 序列、`id`、`noticeType` 必须与官方原文一致。
3. 校验通过才写入，并且是「先写同目录临时文件、再原子改名」，避免出现半截 JSON。
4. 已汉化且内容未变的公告会跳过，不会重复请求服务；「强制重新汉化」会忽略跳过逻辑全部重取。
5. 官方原文会备份到工具箱缓存目录（`%LOCALAPPDATA%\LCTA\notice\originals`），可随时「还原官方原文」。
6. 若服务端一直回 `pending`（等到 60 秒仍未就绪），本次同步会停止，该篇记为「等待服务端」——这不是失败，稍后再点「开始同步并汉化」即可继续。

### 目标语言

工具只写**当前语言**的那一个文件名，语言由公告缓存目录里已有的文件名自动推断。原因：游戏的缓存清理逻辑只把「当前语言」的文件名视为合法，多写的其它语言文件会在下次刷新公告清单（每 ≥10 分钟一次）时被删除。中文系统上游戏使用英文公告，因此自动推断为 `EN`。

### Launcher 集成

开关位于 **Launcher 配置** 页面「工作模式配置」中的「启用公告汉化」，首页「**一键配置**」默认开启；本页仅提供集成介绍与跳转按钮。

开启后，通过 Launcher 启动游戏时会在模组准备阶段做一次增量同步（只处理官方清单里新增或未汉化的公告），并在「Launcher 启动预算」内完成；超时、服务不可用或服务端一直未命中缓存都只记录日志，不会阻塞游戏启动。

注意：未命中缓存时的等待同样受「Launcher 启动预算」约束（默认 30 秒，小于客户端自身的 60 秒上限），预算不足即停手，剩余公告留待下次启动同步。

### 注意事项

- **不要手动改名**：文件名必须与官方清单完全一致，否则会被游戏的清理逻辑当作垃圾删除并重新下载。
- 公告**配图**走 Addressables 资源包，不是文本，本功能覆盖不到。
- 官方发布新公告后需要重新同步；服务不可用或超时时，对应公告保持官方原文，不会被写入残缺内容。
- 「清除本地缓存」页的「清理通知缓存文件」会删除整个公告目录（含译文），之后重新同步即可补回。
- 校验不通过（例如服务端自创了 `formatKey`）时一律不写入：缺少或自创的 `formatKey` 会让整篇公告正文渲染中断。
